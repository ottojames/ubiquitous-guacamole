# Council Portal Audit - Comprehensive PRD

**Date**: 28 January 2026
**Auditor**: Development Orchestrator
**Target**: Council Portal (`/c/{orgSlug}/{deptSlug}/*`)
**Council Tested**: Sample Timboro Council

---

## Executive Summary

The council portal is **fundamentally broken**. It presents a professional-looking UI that conceals significant functional gaps. Key issues include:

1. **Audit logging is completely non-functional** - The audit_logs table exists with proper schema and triggers, but NO logs are being recorded
2. **Billing shows hardcoded mock data** - Displays "£149/month Professional" plan with fake invoices and payment methods
3. **History tab shows hardcoded placeholder content** - Not connected to real audit data
4. **Access controls are misconfigured** - Audit logs restricted to admins only when ALL staff should see them
5. **Documents tab misleads users** - Originally showed fake document links; now shows only real docs but UX is confusing
6. **Demo mode detection scattered throughout code** - Inconsistent handling of test vs production environments

**Principle violated**: "NOTHING should exist just for demo purposes or to look good. Every element must have real functionality."

### P0 - CRITICAL (Blocking / System Broken)

#### P0-001: Audit Logs Not Being Recorded

**Current State**:
The `audit_logs` table exists with proper schema (migration `20251021000006_audit_logs.sql`) including:
- Database triggers for `notices`, `department_memberships`, `organizations`, `departments`
- Function `create_audit_log()` for manual logging
- Function `log_audit_action()` added in later migration

However, the audit log page shows EMPTY because:
1. The triggers call `create_audit_log()` which exists
2. Server routes call `log_audit_action()` RPC which also exists
3. But the AuditLog.tsx queries by `department_id` - triggers may not be populating this correctly
4. No actual activity is generating logs - likely RLS policy blocking inserts

**Expected Behavior**:
Every significant action should be logged:
- Notice created/updated/published/expired
- Team member added/removed/role changed
- Representation received/read/responded
- Settings changed
- Template modified
- Login/logout events

**Root Cause**:
1. RLS policies may be blocking inserts to audit_logs
2. Server-side RPC calls may be failing silently
3. Trigger function `create_audit_log` may not have proper permissions
4. `department_id` not being populated correctly in triggers

**Files Affected**:

- `/Users/ottoclarke/projects/Ralph's Civic Notices/server/routes/internal-comments.ts` (line 271)

**Fix Required**:
1. Verify RLS policies allow audit_logs inserts via SECURITY DEFINER functions
2. Add error handling to RPC calls to surface failures

## What Council Portal SHOULD Show

Based on user requirements, the council portal should display:

### 1. Notice Uploads (Published Notices)
- Real notices published in their jurisdiction
- Status, dates, applicant details
- Proof PDFs when available
- **Currently**: Mostly working, but demo mode detection causes inconsistencies

### 2. Representations
- Real representations from the public
- Internal commenting by staff
- Read/unread status
- Officer responses
- **Currently**: Working, but uses 'demo-user' fallback

### 3. Audit Log (Visible to ALL Staff)
- All actions taken on notices
- Who did what and when
- Filterable by date, action type, user
- Exportable to CSV
- **Currently**: EMPTY due to logging failures, restricted to admins

### 4. Completed Forms
- Application form data
- Template-generated notice text
- Legal compliance fields
- **Currently**: Overview tab shows this data

### 5. Evidence Packs
- Downloadable compilation of notice + representations
- For committee hearings
- **Currently**: Working via EvidencePackDownload component

## Architecture Recommendations

### 1. Single Audit System
Consolidate `audit_logs` and `admin_actions` tables. Use one table with proper categories.

### 2. Remove Demo Mode Entirely
Create a proper test environment instead of runtime demo detection. All code paths should be production-ready.

### 3. Shared Configuration
Create `/src/config/pricing.ts` used by both Pricing page and Billing page.

### 4. Error States Over Fake Data
When data is missing, show informative error/empty states, never fake data.

### 5. RBAC Consistency
Use the existing PERMISSIONS system for all access control, not ad-hoc role checks.
