## 1. Project Overview

### Project Structure
- Use `@/` path alias for imports from src/
- New publish wizard in src/next/publish/flow/ (feature flagged)
- Legacy publish flow in src/pages/PublishPage.tsx (being phased out)
- API server runs on port 5174, Vite dev server on 5173

### Key Components
- Supabase client initialized in src/lib/supabase.ts
- Notice schemas in src/next/publish/schema/registry.ts
- Notice templates in src/next/publish/templates/
- Wizard state management in src/wizard/draftStore.ts (SessionStorage)

### Development Workflow
- Start dev: `npm run dev` (runs both frontend + backend)
- Frontend only: `npm run dev:web` (port 5173)
- Backend only: `npm run dev:server` (port 5174)
- Quality checks: `npm run typecheck && npm run lint && npm test`

### Testing Requirements
- ALL features must be browser tested in Chrome before marking passes: true
- Evidence must include "BROWSER TESTED: [steps performed]"
- Code existence ≠ feature working

### User Context
- Council users: Sarah (Licensing), David (Planning), Priya (Environmental Health)
- Law firm users: Emma (Licensing Solicitor), Thomas (Planning Solicitor)
- See AVATAR_PROFILES.md for detailed personas

### Database & API
- Supabase PostgreSQL with PostGIS for geospatial queries
- Tables: notices, councils, organizations, departments
- Storage bucket: 'notices' for PDFs/images
- Geocoding via postcodes.io (free, no API key)
